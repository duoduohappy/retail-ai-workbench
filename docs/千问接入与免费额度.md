# Qwen4-Max接入与验证

本项目的“真实模型”指后端实际发送API请求，使用模型生成脚本或研究报告，并记录模型ID、请求ID、耗时与Token用量。没有配置或调用失败时，页面会报错并保留原报告；本地规则报告不会被标为真实模型生成。

## Render环境变量

先手动部署包含model_server.py和llm_service.py的版本，再在Render服务的Environment页面填写以下变量。密钥和访问码不要放入GitHub、截图或聊天。

| 变量 | 设置 |
| --- | --- |
| RETAIL_LLM_MODEL | qwen4-max |
| RETAIL_LLM_ENDPOINT | 控制台对应地域的完整Chat Completions地址，末尾为/chat/completions |
| RETAIL_LLM_API_KEY | 在同地域百炼创建的通用API Key，仅填写在Render或本机环境变量 |
| RETAIL_DEMO_ACCESS_CODE | 自己设置一串演示访问码，和API Key不同；公网模型调用必须提供 |
| RETAIL_LLM_MAX_CALLS | 20，默认本进程最多20次尝试 |
| RETAIL_LLM_MAX_OUTPUT_TOKENS | 1800，默认输出上限 |

也可使用RETAIL_LLM_BASE_URL代替完整endpoint，填写以/v1结尾的兼容接口地址。服务会追加/chat/completions。

北京地域旧版地址仍受官方支持：

```text
https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
```

官方目前推荐业务空间专属域名：

```text
https://你的WorkspaceId.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/chat/completions
```

地址、地域、Key和账号权限必须相符。直接复制控制台提供的地址最稳妥，不要把Token Plan/Coding Plan专用凭证与通用按量接口混用。

## 验证步骤

1. 保存环境变量，按Render提示手动重新部署。
2. 打开工作台右上角“AI服务”，先看配置状态。读取配置不会调用模型。
3. 填写自己设置的演示访问码，只在当前页面内存保留，刷新后需重新输入。
4. 点击“实际验证模型连接”。此操作会真实发送一次短请求并消耗Token。
5. 成功后显示模型、用量和耗时，健康接口才会把connectionVerified标为true。
6. 在会员与策略中心的“真实公开数据”页面生成有引用分析，或在研究助手检索后生成模型研究报告。

API Key始终在后端。浏览器只提供演示访问码；访问码不会写入localStorage或发给模型服务。

## 免费额度与调用限制

核查日期：2026-11-23。阿里云中国站官方文档列出北京地域Qwen4-Max可获100万Token新人额度，通常自开通/模型发布/申请通过较晚日期起90天有效。账号实际剩余量、到期时间与权限以自己的控制台为准。

保持“免费额度用完即停”开启。遇到AllocationQuota.FreeTierOnly，服务明确显示额度用尽/过期，不重试、不自动换模型，也不自动转付费。用量记录不是账单核算，项目无法从模型回复中确认你的云端剩余额度。

Qwen4-Max官方默认开启深度思考，本项目为演示显式发送enable_thinking=false，并设置输出上限。模型调用次数限制只在当前进程内生效，服务重启会重置，不能替代云端的用完即停。

腾讯TokenHub也有语言模型新人体验额度，但本次默认按用户选择使用千问。框架兼容其他提供Chat Completions的服务，未对腾讯账号进行实际联通验证。

## 研究质量边界

模型只收到用户显式选择的资料或后端读取的公开数据摘要。研究发现必须引用已提供的来源ID和连续逐字原文；未知ID、伪造摘录、空证据及错误结构会拒绝。引用匹配不证明结论语义或来源真实性，仍需人工复核。

公开数据是2010—2011年的历史交易资料，不是当前竞品监测或实时联网搜索。本项目没有把历史模型分析称为当前市场调查。
