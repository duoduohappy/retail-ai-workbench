# 面试演示稿

## 开场：约1分钟

“我根据岗位六个模块，自主开发了一套零售经营与AI决策工作台。门店经营部分用模拟数据演示完整流程，另用UCI真实历史零售数据做推荐对照评估，并提供千问API生成引用报告的能力。我希望展示如何把经营问题、算法验证、内容生产和团队执行连接起来，并说明验证边界。”

## 经营问题：约3分钟

打开经营驾驶舱，选择最近28天、全部门店。说明净销售额和毛利的变化，点击查看经营诊断，展示客流、转化率和客单价贡献分解。

讲解要点：“这是固定顺序代数分解，贡献可以精确对账，但不能单独证明原因。东区重点SKU的零库存是需要核查的业务线索。”

点击门店下钻，查看原始订单；用右上角问号展示指标口径。说明退货、成本和转化率的分母定义。

## 市场、会员与策略：约3分钟

打开市场与竞品雷达，展示同规格、活动条件与采样时间。说明当前竞品为虚构，实际落地需要接入可靠来源与匹配机制。

打开会员与策略中心，展示RFM分层和算法评估。说明按时间切分、热门基线、未购商品候选与库存过滤，以及模拟数据偏好机制带来的评估限制。

从某个会员查看推荐，再点击某个商品加入促销模拟。计算后检查费用后贡献。默认情景可能显示销量增加但毛利减少，这正是决策所需的对比。

讲解要点：“我不会把销量提升直接等同于经营价值，也不会将模拟弹性包装成真实预测。真实落地需要活动数据与实验。”

补充展示“真实公开数据”：指明2010—2011年英国在线零售、GBP、UCI来源与许可；查看清洗口径、热门基线、时间切分、候选覆盖率和Bootstrap区间。讲清楚指标只适用于符合条件的历史用户，无法证明线上增量。

## 内容生产：约2分钟

从促销结果点击生成活动内容。确认商品和候选价格已关联，生成模板脚本，查看字幕与配音稿，勾选核对项，点击合成当前脚本视频。

浏览器合成约15秒无声WebM；随项目提供的MP4样片则采用真实AI静态图、模板动效和本地语音，已有配音。区分模板脚本、API脚本、AI图像和生成式视频；项目尚未实现实时生成式视频接口。

## 可信研究：约2分钟

打开市场研究助手，运行默认研究问题。查看有效证据、过期E04与同源转载E05的排除记录，点击引用追溯来源。

讲解要点：“日期有效不等于来源可信；多个转载也不等于多个独立证据。当前流程只处理受控资料，真实检索和来源验证需要继续接入。”

若已配置并实际验证千问，展示“AI服务”的成功状态，再生成带来源ID、逐字摘录、耗时与Token用量的模型报告。说明服务器会拒绝伪造引用，但逐字匹配仍不能证明推断正确；目前没有实时联网检索。若尚未完成云端验证，明确说“接口和自动化测试已完成，账号联通待验证”。

## 组织交付：约2分钟

从经营异常或促销结果创建任务，填写业务负责人、预算和验收指标。打开项目与价值管理，修改状态，展示假设ROI与90天阶段方案。

讲解要点：“先统一指标和基线，确定一个有业务负责人的试点，再根据净收益和运营负担决定推广。预算、团队人数和收益目标，需要结合实际现状确定。”

## 常见追问

| 追问 | 回答主线 |
| --- | --- |
| 为什么不用更复杂的推荐模型？ | 先建立可解释基线和数据链路；复杂度由数据量、目标和验证结果决定。 |
| 推荐指标变好了，销售一定增长吗？ | 不一定。离线只验证排序，线上还受库存、曝光和运营影响，需实验观察净毛利及负向指标。 |
| 降价为什么可能不值得做？ | 新增销量可能无法弥补单位毛利损失，还要计活动成本与库存约束。 |
| 如何防止报告编造？ | 结构化证据、时间与范围检查、同源去重、引用追踪、事实与推断分开；信息不足就说明。 |
| 作品里哪些是真AI？ | 推荐实际计算并在真实历史数据上对照；内置商品图是真实AI生成；默认脚本和本地报告为规则模板。千问API可生成脚本和引用研究报告，是否已联通以当前环境实际验证为准。 |
| 如何组织团队？ | 以业务目标和验收拆任务；明确业务、数据、算法、工程、内容的责任与依赖；按阶段审查预算与效果。结合自己的真实管理经历展开。 |
| 怎么迁移到企业？ | 先确认业务与系统，接入数据并对账；再建设身份权限、审计、实验和运维，逐步替换演示数据。 |

## 表达边界

可以说“我自主开发并验证了这套演示项目，具备这些可运行能力”。真实商业成绩、带队经历和资源规模，用本人实际经历支撑。不要将模拟指标当成目标企业经营事实或真实增长成绩。
